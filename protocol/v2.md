# Kolf multiplayer protocol v2 foundation

Protocol v2 uses JSON text messages with a common envelope:

```json
{
  "protocolVersion": 2,
  "type": "SetReady",
  "requestId": "opaque-request-id",
  "lobbyId": "opaque-lobby-id",
  "matchId": "opaque-match-id-when-needed",
  "payload": {}
}
```

`connectionId`, `memberId`, `lobbyId`, `playerId`, `matchId`, and `requestId`
are separate opaque identities. Engine indexes are not network identities. Lobby
configuration uses `lobbyRevision`; committed game state, synchronization rounds,
and replaceable frames use separate `stateRevision`, `syncId`, and `frameSeq`
counters.

The maximum encoded message size is 512 KiB. IDs are 1–96 ASCII letters,
digits, `_`, or `-`. Display names contain 1–32 Unicode scalar values, with no
leading/trailing whitespace or control characters. Runtime codecs validate every
client request before it reaches the lobby domain. Protocol v1 receives
`UnsupportedProtocol` and cannot enter a v2 lobby.

## Compatibility identity

The rules/build identity is independent of checkout location and platform line
endings. Its inputs are every `*.cpp` and `*.h` file recursively under `src`:

1. Convert each path to `/` separators relative to `src` and sort paths by byte
   order.
2. Decode the source as UTF-8 and normalize CRLF and bare CR to LF.
3. SHA-256 each normalized file.
4. Concatenate `kolf-rules-v2\n`, then for every file append
   `<relative-path>\n<lowercase-file-sha256>\n`.
5. SHA-256 that UTF-8 preimage to obtain the compatibility identity.

Course identity remains SHA-256 over the exact raw course bytes. The two hashes
serve different purposes and must not be substituted for one another.

The shared generic-envelope fixture is
[`v2-envelope-fixtures.json`](v2-envelope-fixtures.json). Type-specific payload
fixtures will be added alongside the native lobby integration rather than
expanding a speculative matrix now.
